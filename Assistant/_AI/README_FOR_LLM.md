# README_FOR_LLM

このVaultでは、AIをローカルの自動整理専用ツールではなく、**ユーザーと一緒にVault全体を直接編集するアシスタント**として扱う。

ユーザーから「このノートを直して」「ここに保存して」「整理して」「移動して」などの指示があった場合、AIは実際のVault構成を確認し、最も自然な場所を直接編集する。

## ルールの優先順位

判断が衝突した場合は、次の順で優先する。

1. **その会話でのユーザーの明示的な指示**
2. **現在のVaultで実際に使われている構成・表記・テンプレート**
3. `Assistant/_AI/` のルール
4. 古い慣習・過去のAI生成ノート

このルール自体もユーザーの明示的な指示で変更・無視してよい。

## 作業前に確認するもの

原則として最初にこの `README_FOR_LLM.md` を確認する。
そのうえで、作業内容に応じて必要なルールだけ読む。

- 整理・保存先の判断: `Assistant/_AI/rules.md`
- タグを付ける・直す: `Assistant/_AI/tag_rules.md`
- 名前や保存先の表記ゆれ: `Assistant/_AI/project_aliases.md`
- 新規ノートや定型構造: `Assistant/_AI/templates.md`

さらに、**対象ファイルとその周辺の既存ノートを確認し、現在の運用を優先する**。

## 編集権限

**Vault内の編集可能範囲に制限は設けない。**

AIは、ユーザーの依頼を達成するために必要であれば、Vault内のすべてのファイル・フォルダを対象に以下を行ってよい。

- 読み取り
- 新規作成
- 追記・部分編集
- 全面書き換え
- 移動
- リネーム
- 削除

`.obsidian/`、スクリプト、添付ファイル、既存ノート、AIが過去に作成していないファイルも対象に含む。

Gitで履歴を保存しており復元できることを前提とするため、旧ルールにあった「AIはここを触ってはいけない」というパス単位の禁止は廃止する。

ただし、自由に編集できることと無関係に変更してよいことは同義ではない。変更はユーザーの目的に必要な範囲に留め、既存の有用な情報を意図なく失わせない。大量削除・大量移動・設定変更など影響が大きい操作では、対象と目的を確認したうえで一貫して実行する。

## AIチャット中心の運用

- ユーザーが対象ノートを指定した場合は、そのノートを直接編集する。
- `inbox.md` を経由することを必須にしない。
- 既存ノートに自然な保存先があるなら、AI専用のコピーを作らない。
- Git履歴とチャット履歴を変更履歴として利用できるため、`Assistant/_AI/llm_log.md` への毎回の記録は必須ではない。
- 判断に少し迷うだけで `unresolved.md` に逃がさず、既存構造と文脈から妥当な保存先を選ぶ。

## Vaultの整理方針

### Areaを正本にする

「Project」という専用のAI管理階層を正本にしない。
長く残すノートは、内容に最も近い既存の人間向けAreaへ置く。

例:

- ロボコン → `ロボコン/`
- 授業・勉強 → `授業/`
- 実際に進めているソフトウェア・個人開発 → `開発/`
- まだ着手していないアイデア・いつかやりたいこと → `やりたいこと/`
- PC・環境関連 → `PC/` など既存の該当Area

`Assistant/Projects/` は**旧AI運用のlegacy領域**とする。新しいプロジェクトの標準保存先には使わない。

既存の `Assistant/Projects/` に情報がある場合は無視せず参照するが、同じテーマの人間向けノートが存在するならそちらを正本として更新する。整理・移行を行う際は、重複を減らしてArea側へ寄せる。

### プロジェクトは「フォルダ形式」に固定しない

新しいテーマごとに `overview.md` と `logs.md` のセットを自動生成しない。
まずは1つの分かりやすいノートとして置き、情報量が増えて分割する価値があるときだけ子ノートやサブフォルダを増やす。

## Daily / Tasks

Dailyノートの実際のテンプレートは `テンプレート/YYYY-MM-DD.md` を正本とする。
既存Dailyを編集するときは、そのノートの現在の書き方を優先する。

同じタスクのチェックボックスを複数ファイルへコピーしない。Tasksプラグインのクエリやリンクで参照する。

## 基本原則

- 既存ノートを増殖させるより、適切な既存ノートを育てる。
- 新規ファイルを作る前に、同じテーマのノートが既にないか確認する。
- フォルダ名・タグ・見出しは、理論上の統一より実際のVaultの運用を優先する。
- 日付を明示する場合は原則 `YYYY-MM-DD` を使う。
- AIがGitコミットを作成する場合、コミットメッセージは日本語で書く。
- 人間があとから見返して分かりやすいMarkdownを優先する。
