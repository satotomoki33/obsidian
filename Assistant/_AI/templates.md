# テンプレート・記法の参照

このファイルはAIが新規ノートを作る際の補助資料。
**実際の既存ノートやVault内の現在のテンプレートの方が優先**される。

---

## Daily note

Dailyの正本テンプレートは次のファイル。

```text
テンプレート/YYYY-MM-DD.md
```

新しいDailyを作る場合は、まずこのファイルの現在の内容を確認して合わせる。

現在の基本構造は概ね次の形。

```md
## Tasks

## Schedule

## Logs

## Notes
```

既存Dailyに追記する場合は、テンプレートよりそのノート自身の書式を優先する。

---

## Task

通常のタスクはシンプルなチェックボックスを基本とする。

```md
- [ ] タスク名
```

`#task` は付けない。

期日・優先度・繰り返しなどTasksプラグインの機能が必要な場合だけ、周辺ノートで使われているTasks記法に合わせて追加する。

完了済みタスクを新しく作る必要がある場合も、既存のTasksプラグイン表記に合わせる。

---

## Schedule

予定・試験・試合など、現在のDailyでカレンダー的に扱う項目には `#スケジュール` を使う。

```md
- [ ] 予定名 #スケジュール
```

時刻がある場合:

```md
- [ ] 10:00 予定名 #スケジュール
```

必要な補足がある場合:

```md
- [ ] 10:00 予定名 #スケジュール
  - 場所: 場所名
  - メモ: 補足
```

`#schedule` は旧ルール由来なので、新規では原則使わない。

---

## Log / Note

ログやメモは、タグを必須にせず、そのノートの見出し構造に自然に追加する。

```md
## Logs
- 作業内容
```

```md
## Notes
- メモ
```

`#log` や `#memo` は自動付与しない。

長期保存する内容ならDailyへ埋めたままにせず、必要に応じて該当Areaの既存ノートへ整理する。

---

## テーマ・プロジェクトノート

プロジェクト専用の固定テンプレートは使わない。

まず内容に最も近いAreaへ、テーマ名そのものをファイル名にした1ノートとして作るのを基本とする。

例:

```text
開発/YouTube Walkman Converter.md
ロボコン/SSH切断後にROSを停止する.md
やりたいこと/サイバーデックコントローラー.md
```

内容に応じた例:

```md
# テーマ名

## 概要

## 現状

## 決定事項

## メモ

## 次にやること
```

ただし、この見出しを毎回すべて作る必要はない。情報量と用途に合わせて必要なものだけ使う。

`overview.md` / `logs.md` の2ファイルセットは新規プロジェクトの標準にはしない。

---

## やりたいこと

小さなアイデアは個別ノートを増やさず、既存の一覧へ1項目追加するだけでもよい。

```md
- やってみたいこと
  - 補足
```

設計や調査が増えて1項目では見づらくなったら、`やりたいこと/<テーマ>.md` に分ける。
実際に着手したら、必要に応じて `開発/` など適切なAreaへ移す。

---

## AI作業ログ

`Assistant/_AI/llm_log.md` は必須ではない。
大規模な整理など、Vault内にも履歴を残す価値があると判断したときだけ次のように記録してよい。

```md
## YYYY-MM-DD

- 作業内容
```

---

## 判断不能な内容

通常は既存構造を確認して妥当な場所へ整理する。
本当に保存先を決められず、元情報を失う危険がある場合だけ `Assistant/_AI/unresolved.md` を使う。

```md
## YYYY-MM-DD

### 元の内容

> 元の文章

### 判断に迷った理由

- 理由
```
