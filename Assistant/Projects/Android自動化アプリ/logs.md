# Android自動化アプリ Logs

## 2026-07-30

- iPhoneの「ショートカット」に似た自動化アプリの構想を開始した。
- GUIだけでスクリプトを組む煩雑さを解消するため、GUIとJSONファイルの両方から編集できる設計にする。
- JSONを唯一の正式な保存形式とし、GUIはJSONを視覚的に編集するビューとする方針を決定した。
- 主な用途として、通知監視、時間帯による処理、通知タップ・ウィジェットタップによるアプリ起動を想定した。
- OS制約を考慮し、初期版はAndroid向けとする。
- バックグラウンドから直接別アプリを開くのではなく、確認通知を出し、その通知タップからアプリを開く方式を基本とする。
- Kotlin、Jetpack Compose、NotificationListenerService、AlarmManager、WorkManager、Roomなどを技術候補とした。
- MVPは、手動・ウィジェット・時刻・通知をトリガーに、アプリ起動・URL表示・通知表示を実行できる範囲とした。
- 通知の無限ループ、連続発火、外部編集競合、壊れたJSONの上書きを防ぐ安全機構が必要。

### 決定事項

- Android先行
- Kotlinネイティブを優先
- `WHEN / IF / DO` モデルを採用
- JSONを正本とする
- GUI編集とJSON編集を同じWorkflowモデルへ反映する
- 実行履歴と失敗理由を保存する

### 未解決事項

- 正式名称
- JSON Schemaの詳細
- GUIの形式
- 変数・分岐・ループの対応範囲
- Google Play配布とAPK配布の優先順位
