# エミュ機改造 Logs

## 2026-07-30

### 発端

Linux系の携帯エミュレーターゲーム機へキーボードや外部画面を接続し、ゲーム以外にも使える携帯Cyberdeckへ改造する案を検討した。

参考イメージは、縦型の携帯ゲーム機上でDebian系Linuxのデスクトップやターミナルが動いている構成。単なる小型PCではなく、ゲーム機のコントローラーと筐体を活かした端末にしたい。

### 決定した主要機能

- 普通の携帯エミュレーターとしてゲームができる
- 本体単体で登録済みスクリプトやアクションを呼び出せる
- キーボードと外部画面を接続し、SSH経由で開発できる
- Androidと外部画面を使ってブラウザを閲覧できる

### 中心機能

キーボードがない状態でも、コントローラーから実行したい操作を選べる「Action Deck」を中心機能とする。

想定例:

- IPアドレス表示
- バッテリー・CPU温度表示
- 自宅PCへの接続確認
- SSH接続
- tmuxセッションへの復帰
- Git状態確認
- Obsidian同期
- ROS 2ノード・トピック確認
- rosbagやサービスの状態確認

### 利用方針

- 普段はゲームモード
- 定型操作はAction Deck
- 外部キーボードと画面を接続したときはSSH開発モード
- Web閲覧はAndroidへ役割分担
- 重い処理は遠隔PCで実行
- 本体では入力、表示、接続、軽量処理を担当

### 開発方針

- 最初から筐体を切ったり基板を改造したりしない
- まず市販のケーブル、ハブ、キーボードで成立を確認する
- ゲーム機としての安定性を優先する
- Action DeckはPython、evdev、pygame、YAMLなどで試作する
- 純正OS用microSDを保存し、改造用microSDを分ける
- 設定とスクリプトはGit管理する

### 機種候補

第一候補をANBERNIC RG353Vとした。

理由:

- LinuxとAndroidの役割分担がしやすい構成に近い
- 縦型筐体がCyberdeckのイメージに合う
- 外部画面、USB入力、Wi-Fi、ゲームパッドを組み合わせやすい
- 1号試作機として扱いやすい

ただし購入は未決定。次の点を確認してから判断する。

- Androidでのブラウザ性能
- Linux側の現在のOS対応とパッケージ自由度
- 外部画面の解像度とOS別挙動
- OTGと給電の同時利用
- USBハブ、キーボード、マウスの同時利用
- 中古価格とバッテリー状態

RG353VSなどAndroidを利用できないモデルは、今回の要件から外す。

### 初期MVP

1. ゲームを通常通り起動できる
2. Linuxから本体ボタン入力を取得できる
3. 本体ボタンで5個程度のアクションを選択・実行できる
4. HDMIとキーボードを接続してSSHできる
5. Androidでブラウザと外部画面を利用できる

### 次に検討する内容

- RG353Vと他候補の最新仕様比較
- Action DeckのPC上プロトタイプ
- 本体ボタンコードの調査方法
- 外部画面向けLinux表示環境
- USBハブ・給電構成
- SSH鍵、tmux、接続先設定
- 将来的な着脱式キーボードとドック形状
