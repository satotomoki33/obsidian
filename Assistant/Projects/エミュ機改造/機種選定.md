# 機種選定

## 目的

このノートでは、エミュ機改造プロジェクトのベース端末を選ぶための条件、候補、検証項目を整理する。

ゲーム性能だけでなく、Linux、Android、外部画面、USB、SSH、コントローラー入力、復旧性を重視する。

## 選定方針

優先順位は次の通り。

1. プロジェクトの4つの利用モードが成立すること
2. Linux側を改造・復旧しやすいこと
3. 外部画面と入力機器を同時利用できること
4. ゲーム機として普通に使いやすいこと
5. 試作機として壊しても痛すぎない価格であること
6. 見た目がCyberdeckとして格好よいこと
7. エミュレーター性能が高いこと

高性能でもLinux側を自由に触れない端末は優先度を下げる。逆に、Linuxが自由でもAndroidブラウザと外部画面が成立しない端末は今回の要件から外れる。

## 必須条件

| 項目 | 条件 | 確認方法 |
|---|---|---|
| Linux | ゲーム用Linuxまたは一般Linuxが利用可能 | 対応OS、導入手順、実機報告 |
| Android | Androidを利用可能 | 製品仕様、起動方法、Google Play可否 |
| 外部画面 | HDMIまたはUSB-C映像出力 | 解像度、ミラー/拡張、OS別挙動 |
| USB入力 | キーボード・マウスを接続可能 | OTG、ハブ、Bluetooth |
| ネットワーク | Wi-FiからSSH可能 | 2.4/5GHz、接続安定性 |
| 入力取得 | Linuxから本体ボタンを読める | `/dev/input/event*`、evdev |
| 復旧 | microSDやイメージから戻せる | 純正イメージ、デュアルSD構成 |
| ストレージ | OS・ROM・スクリプトを分離しやすい | microSDスロット構成 |

## 推奨条件

- RAM 4GB以上
- 64bit ARM
- 5GHz Wi-Fi
- Bluetooth
- 720p以上の外部出力
- 充電とUSB OTGを同時利用可能
- 充電用とOTG用の端子が分離
- H.264/H.265ハードウェアデコード
- コミュニティOSが活発
- Debian系ユーザーランドを利用しやすい
- 本体画面がターミナル表示に耐えられる
- 本体を分解せずmicroSDを交換できる

## 購入前に必ず確認する点

### Linux

- 現在利用できるOS名と更新状況
- SSHサーバーまたはクライアントを導入できるか
- Python、evdev、pygameなどを導入できるか
- root権限またはパッケージ導入手段があるか
- 読み取り専用ルートファイルシステムではないか
- Wayland、X11、フレームバッファのどれを使うか
- EmulationStationから任意アプリを起動できるか

### Android

- Androidのバージョン
- Google Playまたは代替ストアを利用できるか
- ブラウザが実用速度で動くか
- HDMI出力時の解像度
- 外部マウスの右クリック・スクロール
- 外部キーボードの日本語配列
- 画面出力中の発熱とバッテリー消費

### HDMI・USB

- 本体起動前にHDMI接続が必要か
- 本体画面と外部画面の同時表示可否
- 720p、1080pの選択可否
- AndroidとLinuxの両方で映像が出るか
- USBハブが利用できるか
- OTG中に充電できるか
- 有線LANアダプターを利用できるか
- 映像出力とUSB入力を同時利用できるか

### 復旧・改造

- 純正OSイメージが入手できるか
- microSDだけで試せるか
- 内蔵ストレージを書き換えずに済むか
- 文鎮化した場合の復旧方法があるか
- コミュニティに分解・修理情報があるか

## 現在の第一候補: ANBERNIC RG353V

### 第一候補にする理由

- LinuxとAndroidを役割分担する構想に近い
- 縦型筐体が今回のCyberdeckイメージに合う
- 画面、バッテリー、コントローラー、Wi-Fiが最初から一体化している
- 外部画面とUSB機器を追加するだけで試作を開始できる
- 本体単体でも普通のレトロゲーム機として成立する
- 高価な端末を改造するより1号試作機として扱いやすい

### 想定する役割

| モード | RG353Vでの想定 |
|---|---|
| ゲーム | Linux側のゲームフロントエンド |
| Action Deck | Linux側にPythonアプリとして追加 |
| SSH開発 | 外部画面・キーボード・SSH |
| ブラウザ | Android側のブラウザ |
| リモート | SSH、Moonlight、リモートデスクトップ |

### 懸念点

- AndroidブラウザにはRAM・SoC性能の余裕が少ない可能性がある
- 重いWebアプリや多数タブには向かない可能性がある
- Linuxディストリビューションによってパッケージ導入の自由度が異なる
- AndroidとLinuxで外部画面の挙動が異なる可能性がある
- OTGと充電の同時利用可否を実機情報で確認する必要がある
- 古い中古個体ではバッテリー劣化の可能性がある

### 型番の注意

**RG353VとRG353VSを混同しない。**

今回の構想ではAndroidブラウザモードが必要なため、Linuxのみの構成は基本的に対象外とする。購入ページでは製品名、RAM、Android対応を必ず確認する。

## 比較候補

以下は会話時点の比較候補。仕様・OS対応・販売状況は購入時に最新情報を確認する。

### Retroid Pocket 5系

想定する強み:

- Androidブラウザとリモートデスクトップの性能に余裕が期待できる
- 高解像度画面でWebやターミナルを見やすい
- USB-C映像出力とドック構成を組みやすい可能性がある

懸念:

- Linux側の自由度とAction Deck組み込み方法を確認する必要がある
- 価格が上がる
- 映像・給電・USB入力をまとめるドックが必要になりやすい
- 横型で、今回イメージしている縦型Cyberdeck感は弱い

向いている場合:

- AndroidブラウザとMoonlightを重視する
- 多少高価でも実用性を優先する

### RG552

想定する強み:

- 大きめの画面でLinuxやAndroidを操作しやすい
- 机上端末に近い使い方をしやすい

懸念:

- 本体が大きく携帯性が下がる
- 古い中古個体ではバッテリー状態に注意が必要
- 外部画面中心なら本体画面の大きさを活かしにくい

向いている場合:

- 安い中古が見つかり、本体画面も積極的に使いたい

### RG353P系

想定する強み:

- RG353Vに近いソフトウェア構成を横型筐体で試せる可能性がある
- 長時間ゲームでは縦型より持ちやすい可能性がある

懸念:

- Cyberdeckらしい縦型の見た目から離れる
- 型番ごとのAndroid対応を確認する必要がある

向いている場合:

- 見た目よりゲーム機としての持ちやすさを優先する

### RG ARC-D系

想定する強み:

- ボタン中心のAction Deck操作には相性がよい
- 独特の筐体で変態端末感がある

懸念:

- アナログスティックがない構成では、一般GUIのマウス操作に不利
- ブラウザやリモートデスクトップを本体操作する用途には弱い

向いている場合:

- Action Deckと格闘・レトロゲームを優先し、一般GUI操作を外部マウスに任せる

## 端末を買う前の検証手順

### Step 1: 仕様表で落とす

次のどれかに該当する機種は除外する。

- Androidが使えない
- 外部映像出力がない
- USBキーボードが使えない
- Wi-Fiがない
- microSDからLinuxを起動できない
- RAM 1GBのみ

### Step 2: OS情報を確認

- 対応OSの公式・コミュニティページ
- 最終更新日
- GitHubのissue
- SSH導入例
- パッケージ追加例
- `/dev/input`利用例

### Step 3: 実機動画・レビューを確認

検索する内容:

- 機種名 HDMI output Linux
- 機種名 Android HDMI keyboard mouse
- 機種名 OTG charging simultaneously
- 機種名 SSH terminal
- 機種名 custom firmware
- 機種名 browser performance

### Step 4: 中古購入時の確認

- バッテリー膨張・劣化
- 画面焼け・変色
- スティックドリフト
- USB端子の緩み
- HDMI端子の接触
- microSDスロット
- Wi-Fi接続
- Android起動可否
- 充電器・ケーブルの有無

ROM入りmicroSDや収録ゲーム数には追加料金を払わず、本体状態を優先する。

## 購入後すぐに行う試験

筐体を加工する前に、次の順で確認する。

1. 純正状態の写真と設定を保存する
2. 純正microSDをイメージ化する
3. ゲームを起動する
4. Wi-Fiへ接続する
5. LinuxからSSH接続する
6. `/dev/input/event*`で本体ボタンを確認する
7. HDMIで外部画面へ出力する
8. USBキーボード・マウスを接続する
9. Androidを起動する
10. Androidでブラウザを開く
11. Androidから外部画面へ出力する
12. OTG・給電・HDMIを同時利用する

## 機種決定の合格条件

次の4シナリオが無改造で成立する機種を採用する。

### ゲーム

本体単体でゲームを選択・起動・終了できる。

### Action Deck

Linuxから本体ボタン入力を取得し、任意のローカルスクリプトを実行できる見込みがある。

### SSH開発

外部画面とキーボードを接続し、SSHで遠隔PCへ接続できる。

### Androidブラウザ

Androidでブラウザが動き、外部画面と入力機器を利用できる。

## 現在の結論

- 現時点ではRG353Vを第一候補とする
- RG353Vを購入決定とはせず、外部出力・USB・OS自由度を調査する
- RG353VSなどAndroid非対応モデルは避ける
- ブラウザ性能を重視する場合はRetroid Pocket 5系と比較する
- 価格よりも、4つの利用モードが無改造で成立するかを優先する
