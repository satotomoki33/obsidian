# フィルタあり実験の正しい流れ

重要なのは、**攻撃開始後に `attacker_search.sh` を実行して、その直後に iptables を保存する**こと。

## 例：100_filter

### Webサーバ側

```bash
cd ~/attacker_search/result

sudo iptables -F
sudo iptables -P INPUT ACCEPT
sudo iptables -P FORWARD ACCEPT
sudo iptables -P OUTPUT ACCEPT

sudo /etc/init.d/apache2 restart
sudo sysctl -w vm.drop_caches=3

free -k > free_before_100_filter.log
sudo wc -l /var/log/apache2/p3/access.log > access_before_100_filter.txt

top -b -d 1 -n 180 > top_100_filter.log &
vmstat 1 180 > vmstat_100_filter.log &
```

### 攻撃サーバ側

```bash
sed -i 's/^TIMER_AFTER_URL_SLEEP=.*/TIMER_AFTER_URL_SLEEP=100/' sample.cnf
grep TIMER_AFTER_URL_SLEEP sample.cnf

sudo curl-loader -f sample.cnf 2>&1 | tee curl_100_filter.out
```

### Webサーバ側、攻撃開始から5〜10秒後

ここが一番大事。

```bash
cd ~/attacker_search

./attacker_search.sh | tee result/attacker_search_100_filter.out

sudo iptables -L INPUT -n > result/iptables_100_filter.txt
cat result/iptables_100_filter.txt | head -30
```

ここで `DROP 192.168...` が出ていれば成功。

### Webサーバ側、終了後

```bash
cd ~/attacker_search/result
free -k > free_after_100_filter.log
sudo wc -l /var/log/apache2/p3/access.log > access_after_100_filter.txt
```

## 成功判定

各 filter 実験で、これを見てください。

```bash
cat ~/attacker_search/result/iptables_100_filter.txt | head -30
cat ~/attacker_search/result/iptables_200_filter.txt | head -30
cat ~/attacker_search/result/iptables_400_filter.txt | head -30
```

成功ならこういう行が出ます。

```text
DROP       tcp  --  192.168.131.xx       0.0.0.0/0            tcp dpt:80
```

これが出ていれば、レポートで「攻撃者IPを検出して遮断した」と書けます。

今の状態では `iptables_*.txt` にDROPがないので、**filter 3条件だけ取り直し推奨**です。


```
sudo awk '
$1 != "::1" {
    time=$4
    gsub(/\[/, "", time)
    print $1, time
}
' /var/log/apache2/p3/access.log | sort | uniq -c | sort -nr | head -5
```
