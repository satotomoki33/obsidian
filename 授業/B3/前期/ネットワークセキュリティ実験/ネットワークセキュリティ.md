4. シェルスクリプト

シェルスクリプトで Hello World
```
#!/bin/sh
# Display text string
echo "Hello World"
```

  - 1行目: 「シバン」(shebang)と呼ばれるインタプリタ指定部（#! の2文字は、他のスクリプト言語でも用いられる）
  - 2行目: コメント文 (1行目の先頭 # とは異なる)
  - 3行目: 文字列 Hello World を echo コマンドで出力

※この実験では、Bash 文法ではなく、sh (Bourne Shell) を用います。

シェル変数
```
#!/bin/sh
MOJI="letters"
NUMBER=123
DATE=`date`
echo "MOJI = $MOJI"
echo "NUMBER = $NUMBER"
echo "DATE = $DATE"
```

  - シェル変数: MOJI, NUMBER, DATE
      - 代入: 等号記号 = を用いる（前後に空白を入れない）
      - 値参照: シェル変数の前に $ を付ける（${変数名} と書くことも出来る）
      - 中身: 文字列（数字列の場合は数値とみなす）

シェル変数: ダブルクォーテーション

スクリプト中身:
```
#!/bin/sh
MOJI="letters"
echo "MOJI = $MOJI"
```
実行結果:
```

$ ./command
MOJI = letters
```

→ ダブルクォーテーション内ではシェル変数は展開される

シェル変数: シングルクォーテーション

スクリプト中身:
```
#!/bin/sh
MOJI="letters"
echo 'MOJI = $MOJI'
```
実行結果:
```
$ ./command
MOJI = $MOJI
```

→ シングルクォーテーション内ではシェル変数は展開されない

シェル変数: バッククォート

スクリプト中身:
```
#!/bin/sh
DATE=`date`
echo "DATE = $DATE"
```
実行結果:
```
$ ./command
DATE = Wed Apr 17 12:34:02 JST 2019
```
→ コマンドの実行結果（標準出力）が変数に格納される! （バッククォート ` の代わりに $(date) も使えます）

シェル変数: 代入の際の注意

スクリプト中身:
```
#!/bin/sh
MOJI = "letters" # ← = の前後に空白を入れた
echo "MOJI = $MOJI"
```
実行結果:
```
$ ./command
MOJI: command not found
```
MOJI を、シェルが = と "letters" をコマンドライン引数とするコマンドと見なして実行に失敗する。 → = の前後は空白を入れないように!

制御構文: if （条件分岐）
```

#!/bin/sh
if [ Condition 1 ]
then
    Process 1
elif [ Condition 2 ]
then
    Process 2
else
    Process 3
fi
```


  - if で始まり、fi で閉じる
  - then や else の次は字下げ推奨
  - if の後ろに [ Condition1 ] などを書く
      - Condition には比較演算などを書く（詳しくは資料参照）
      - if と [ や、[ と Condition と ] の間は空白を1文字以上入れる

制御構文: while （繰り返し）
```
#!/bin/sh
while [ Condition ]
do
    process
done

```

  - Condition が成り立っている間、処理を続ける
  - 処理を do と done で囲む（よくある繰り返し処理）

制御構文: for （リストの繰り返し）
```

for variable in e1 e2 e3 ...
do
    process
done
```

  - リスト e1, e2, e3,... の順で処理をする（それぞれ文字列）
  - 処理を do と done で囲むのは while と同じ
  - 処理は、リストの末端で必ず終わる（while とは異なる）

test コマンド(1)

  - if / while コマンドの条件文の括弧 [ は、「test コマンド」と呼ばれる
  - 以下は同じ意味を持つ：
      - [ Condition ]
      - test Condition （[ コマンドを使う場合は閉括弧 ] が必要）
  - [Condition] と書いてしまうと、それがコマンドと誤認される → Condition 前後に空白を入れる必要あり
  - if[ Condition ] もダメ! → if [ Condition ] の様に空白を入れよう!

test コマンド(2)

testコマンドの実行結果は「何も表示しない」

```sh
$ [ 3 -gt 1 ]
$
```

終了ステータスを $? で確認してみよう!

```sh
$ [ 3 -gt 1 ]
$ echo $?
0

$ [ 3 -gt 4 ]
$ echo $?
1
```

test コマンド(3)

  - シェルスクリプトでの真偽は C言語とは逆
      - True: 終了ステータス 0
      - False: 終了ステータス 0 以外
  - if（や while）コマンドの挙動
    1.  if コマンドの直後のコマンド [ の終了を待つ
    2.  [ の終了ステータスが 0 ならば then ブロックへ進む
  - 次の様な文も書ける:

```sh
#!/bin/sh
if gcc sample.c -o sample
then
    echo "コンパイルできました!"
else
    echo "コンパイルに失敗しました!"
fi
```

5. sed & awk (+ grep)

AWK: 最も古い部類のスクリプト言語

  - C言語 の様な構文（AWK の K は Kernighan の K）
      - 変数: 使用時に初期化される（0 または空文字）
  - 処理の流れ:
    1.  BEGIN ブロック: 初期化などの前処理
    2.  「レコード」（通常は1行）づつ読み込む
    3.  パターンにマッチした行に関して何かアクションする（空白で区切られた単位を「フィールド」と呼ぶ）
    4.  END ブロック: テキスト全体を読み終えた後の処理

```awk
#!/usr/bin/awk -f
BEGIN {
    前処理
}
パターン {
    アクション
}
END {
    後処理
}
```

AWK: コマンドとして使う基礎

AWK はコマンドとして使う場合が多い:

```sh
$ awk -F"区切り文字列" 'BEGIN{前処理} パターン{アクション} END{後処理}'
```

次は上記と同じ:

```sh
$ awk 'BEGIN{FS="区切り文字列"; 前処理} パターン{アクション} END{後処理}'
```

入力テキストの第1・第3・第5フィールドを表示する:

```sh
$ awk '{ print $1, $3, $5 } '
```

入力テキストの第2フィールドに文字「hoge」がある行を表示:

```sh
$ awk '$2 ~ /hoge/{ print $0 }'
```

sed: ストリームエディタ

  - エディタの系図:
      - ed: 原始的なラインエディタ
          - ex: ed の機能強化版
              - vi: スクリーンエディタ + ex 機能 (Vimなど)
          - sed: 標準入力ストリームの動的編集ツール
  - AWK の様な変数は無い（厳密に言えば「パターンスペース」と「ホールドスペース」の2つのみ存在する）
  - 頑張れば何でも出来る(計算万能)だが無理は禁物。適宜 AWK を使おう!

sed: 一般的な使用法

正規表現を用いて編集する。

マッチした文字列(hoge)を置換する:

```sh
$ cat hoge.txt | sed 's/hoge/fuga/'
```

HTMLのタグを取り除く:

```sh
$ cat hoge.txt | sed 's/<[^>]*>//g'
```

行後方のカンマ位置の前後を入れ替える（sed は、「最長最左の文字列マッチング」を試みる）:

```sh
$ cat hoge.txt | sed 's/\(.*\),\(.*\)/\2,\1/g'
```

正規表現の例

  - . : 任意の一文字（文字集合全体）
  - * : 文字集合の繰り返し
  - [a-zA-Z0-9] : アルファベット数字 (POSIX では [[:alnum:]] も使える)
  - [^abc] : 「abc 以外の文字集合」を表す（補集合）
  - ^ : 行頭を示す
  - $ : 行末を示す
  - \(RegularExpression\) : マッチする文字列を \1, \2, \3... で参照する

grep(1): 文字列検索コマンド

ただの文字列検索:

```sh
$ cat hoge.c | grep 'printf'
```

HTML や XML タグのある行を表示する:

```sh
$ cat hoge.txt | grep '<[^>]*>'
```

マッチしない行を表示:

```sh
$ cat hoge.txt | grep -v 'abc'
```

ファイル指定でも動作する:

```sh
$ grep 'abc' hoge.txt
```

grep(2): 代替方法

awk の場合:

```sh
$ awk '$0 ~ /abc/{print}' hoge.txt
$ awk '/abc/' hoge.txt # 省略記法
```

sed の場合:

```sh
$ sed '/abc/p' hoge.txt
```

7. 攻撃者判定実験

攻撃者判定スクリプト

  - フィルタリングは iptables の DROP によって行う（自分で調べてください!）
  - スクリプトでは「1秒間に3回以上のアクセスを行うもの」を攻撃者とする。
      - ログのタイムスタンプが同じIPアドレスを、攻撃者と見做す。
  - 攻撃者判定には /var/log/apache2/p3/access.log を使用する。
      - 「IPアドレス・タイムスタンプ」だけでなく、「GET のリクエストファイル」も対象とする。
      - GET リクエストファイルを含める理由: Web サーバへの一度のアクセスでは、通常、同一IPアドレスから数多くの GET
        リクエストがある。そのため、単に「1秒間に3回以上の同一IPアドレスからのアクセス」とすると、一般のクライアントまで弾いてしまう可能性が高いため。

実験方法

  - 攻撃者判定スクリプトは、無限ループで実行しておく
      - 攻撃はいつされるかわからないため。
      - 攻撃が終わってしばらくしたら、Ctrl-C などで停止する。
  - 端末の起動枚数:
      - Webサーバ端末: 2枚 (判定スクリプトを動かす / top のログを取る)
      - 攻撃用サーバ端末: 1枚 (Webサーバで2つを実行直後に curl-loader を実行する)
  - 1つのパラメータで攻撃者判定実験の top ログを取り終えたら?
    1.  判定スクリプトを Ctrl-C で停止
    2.  Apache の再起動・メモリキャッシュのクリア
    3.  sample.cnf のパラメータを変更し、次の実験をする

攻撃者判定(1): 基本的な考え方

1.  curl-loader で Web サーバを攻撃し、そのアクセスログを見る → 大量のログが残されるが、ログは「幾つかのフィールドが並ぶ表」

    ```sh
    $ sudo more /var/log/apache2/p3/access.log
    ```
2.  1秒あたりの攻撃頻度を確認する

    ```sh
    $ sudo more /var/log/apache2/p3/access.log | awk '{print $4}' | sort | uniq -c
    ```
3.  「IPアドレス・タイムスタンプ・ファイル」に揃えて処理をする

    ```sh
    $ sudo more /var/log/apache2/p3/access.log | awk '{print $1, $4, $7}' | sort | uniq -c
    ```
4.  ループバックアドレス（::1）の情報を排除する

    ```sh
    $ sudo more /var/log/apache2/p3/access.log | grep -v '^::1' | awk '{print $1, $4, $7}' | sort | uniq -c
    ```
5.  手順4 の結果の第1フィールドは各タイムスタンプ毎の攻撃頻度になる → その情報から、攻撃候補IPアドレスを特定する

攻撃者判定(2): スクリプトの作り方の基本

0.  実験環境
      - 攻撃は curl-loader がいつ実行されるか実験者は知っているが、一般的な攻撃ではそうではない!
1.  一般的な攻撃の特徴
      - 攻撃がいつ始まって、いつ終わるか判らない。
      - アクセスログは延々と伸び続ける可能性がある。
2.  増え続けるログのリアルタイム解析が必要
      - わざと、数秒ウェイトを入れる（後述）
      - 攻撃で伸びた分のログ切り取って、「攻撃者判定(1)」を試す。
      - ログが伸びた分だけ攻撃者判定を行い、攻撃候補IPアドレスを獲得する。
3.  これを繰り返すと、攻撃者のパケットを iptables がブロックする。
      - 攻撃者は、二度と Apache にアクセスできない
      - → 何度も攻撃しても、サーバの負荷は増えない（はず）

攻撃者判定(3): 攻撃候補IPの重複登録を回避

  - アイデア: 攻撃が一段落した後のログを分析するのは簡単だが、攻撃は続くため、増えたログだけ「攻撃者判定(1)」を実行する。
  - アルゴリズム:
    1.  空のテキストファイル blacklist.txt などを用意する（中身: 既に iptables に登録されているIPアドレスリスト）
    2.  新しく検知した攻撃候補IPアドレスを1つずつ取り出し、blacklist.txt に入っているか grep -w で確認する。
          - 入っていない場合: iptables にIPを登録し、blacklist.txt に追加する。
          - 入っている場合: IPは登録済みなので処理をスキップする。
  - grep -w の使用理由: 検索文字列が「単語」として存在するか調べるため。（例: 192.168.0.1 が 192.168.0.11
    の部分文字列として誤判定されるのを防ぐ）
  - 注: iptables -L の出力結果でブラックリストの代用も可能です。

攻撃者判定(4): ログの切り出し

1.  無限ループでログを読み続ける
      - 攻撃がない状態での空回りを防ぐため適切なウェイトを入れる（sleep 3 など。秒数調整は各自判断）
2.  ログを読み始める行の管理
      - スクリプト起動直後: 1行目（シェル変数 CURRENT 等に行数を保存。初期値は1）
      - 次回を指しておく: 前回ログを読み終えた行（シェル変数 NEXT 等に現在のログ行数を保存）
3.  ログ現在行数の獲得方法: wc -l コマンドを用いて行数を得る

    ```sh
    NEXT=`sudo more /var/log/apache2/p3/access | wc -l`
    ```
4.  ログの切り出し: 次の方法で $CURRENT 行以降のログを表示する

    ```sh
    sudo tail -n +$CURRENT /var/log/apache2/p3/access | ...
    ```

攻撃者判定(5): ログの切り出しの注意点

  - 新たに伸びたログ断片だけを切り出すと、攻撃途中で切り出した断片が離れてしまう恐れがあります。
    [ログ断片1]  隙間  [ログ断片2]
                       ↑ ここが NEXT だと隙間を無視してしまう
  - そこで、敢えてログ断片の切り出しを重複させます。
    [ログ断片1……]
              [ログ断片2………]
                        [ログ断片3……]
  - 一部重複させることで、攻撃者の取りこぼしが減ります。NEXT と CURRENT の更新時期を上手く調整しましょう。

攻撃者判定(6): 攻撃者IPリストの処理

「攻撃者候補IPアドレス」がファイルに格納されていると仮定した場合のループ処理の例：

for を用いる場合:

```sh
for IP in `more 攻撃候補リスト`
do
    処理
done
```

while を用いる場合:

```sh
more 攻撃候補リスト | while read IP
do
    処理
done
```

  - while の場合は、次のようにも書けます: while ... ; do ... ; done < $FILE
      - パイプで繋ぐ場合: プロセス間通信なので若干遅い
      - ファイルからリダイレクト入力する場合: 若干速い

攻撃者実験: 注意事項

  - スクリプトと top による観測は同時実行する
  - top ログのファイル名は top_detect_100.log など解りやすい名前にする
  - top の計測時間は 1秒単位 で、計測時間は 150秒以上 で行う
      - 「基礎実験」と「攻撃者検知実験」の top ログの取り方例:

        ```sh
        $ top -b -d 1 -n 150 > top_detect_100.log
        ```
      - 攻撃後、再度攻撃してみると、攻撃者検知を実感できます。
  - こまめにバックアップ: 「サーバのバックアップ方法」を参照。Windows では WinSCP が便利（プロトコルは SCP を選択）
  - パイプが長すぎる場合はバックスラッシュ（\）で改行できます:

    ```sh
    sudo more /var/log/apache2/p3/access.log | grep -v '^::1' \
        | awk '{print $1, $4, $7}' | sort | uniq -c |  ...（続く）
    ```
  - 基礎実験と同様、パラメータを変更する度に、「Apache 再起動」と「メモリキャッシュクリア」を忘れずに。
