調べた。対象は `tutrobo/abu2026-ros2-ws` の `main` にある `dog3_rtcl` の現行定義。ここでは**ソフトウェア上で定義されているCAN基板・アクチュエータ・センサの接続**を整理している。

## IDの読み方

`EToF番号 / CANバス / 基板ID / 基板内ID`

例：

```text
16 / CAN2 / Robomas基板1 / Motor ID3
```

Robomas・Robstrideは、コード内の `index 0～3` が実際の表示上の **Motor ID 1～4** に対応する。

# EToF1：ID 16

## CAN1：ODrive系

|CANデバイスID|接続先|位置・用途|
|--:|---|---|
|**0**|走行用ODrive|前右|
|**1**|走行用ODrive|後右|
|**2**|走行用ODrive|前左|
|**3**|走行用ODrive|後左|
|**4**|合体昇降ODrive|`docking_lift`|
|**5**|槍昇降ODrive|`staff_lift`|

ODrive ID 0～5の割当はCANアドレス定義にあり、走行輪0～3の物理位置は `前右→後右→前左→後左` の順。

### 走行モジュールの組み合わせ

|車輪|走行ODrive|操舵Robomas|操舵磁気エンコーダ|
|---|--:|--:|--:|
|前右|ID **0**|基板2・Motor ID **1**|基板ID **1**|
|後右|ID **1**|基板2・Motor ID **2**|基板ID **2**|
|前左|ID **2**|基板2・Motor ID **3**|基板ID **3**|
|後左|ID **3**|基板2・Motor ID **4**|基板ID **4**|

走行、操舵、磁気エンコーダは同じ配列indexで対応付けられている。

## 注意点

- `CanIo` はEToF末尾 **16・17・18** を受信対象にしているが、dog3の現在のアドレス定義で実際に機器が割り当てられているのは **16と17**。18番には対応するdog3デバイス定義が見当たらなかった。
    
- 光電センサ部分に「`TODO: ID未設定`」という古そうなコメントが残っているが、実際のアドレスは基板ID **1・2・3** として定義されている。
    
- Solenoid・SW Sensorの `index` はコード上の0始まり表記。基板シルクの端子番号と対応させる場合は、実機配線図か基板側ファームウェアも確認した方が安全。
